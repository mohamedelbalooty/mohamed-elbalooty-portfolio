# Production Deployment & DevOps Guide
## Mohamed Elbalooty Portfolio (`mohamed-elbalooty-portfolio`)

This document is the authoritative, repository-specific deployment guide for the personal portfolio and CV website of Mohamed Elbalooty. It covers architecture decisions, local verification, static export behavior, Firebase Hosting classic configuration, automated CI/CD via GitHub Actions, SEO operations, custom domain setup, rollbacks, and recovery protocols.

---

## 1. Overview

- **Production Architecture**: Next.js 16 (App Router) + React 19 + Tailwind CSS v4, built as a 100% static site export (`output: "export"` in [next.config.ts](file:///d:/vibe%20coding/mohamed-elbalooty-portfolio-cv/next.config.ts)) generating static HTML, CSS, client-side JS bundles, and static assets in `./out`.
- **Why Static Export**: Eliminates server runtime vulnerabilities, removes cold start latency, requires zero maintenance of Node servers, offers extreme resistance to traffic spikes, and runs at zero cost on global CDNs.
- **Why Firebase Hosting Classic**: Firebase Hosting classic distributes static content across Google's worldwide SSD-backed Edge CDN, includes automatic SSL certificate management, supports preview channels with isolated URLs, natively handles clean URLs, and operates on the no-cost **Spark (Free)** plan without requiring billing or credit card credentials. Firebase App Hosting / SSR runtimes are deliberately omitted because the portfolio requires no server-side Node.js compute.
- **Source Control**: GitHub repository [`mohamedelbalooty/mohamed-elbalooty-portfolio`](https://github.com/mohamedelbalooty/mohamed-elbalooty-portfolio). The default production branch is `master`. Feature development occurs on `develop`.
- **CI/CD Automation**: GitHub Actions handles reproducible testing, static generation, preview channel deployment on pull requests, and live deployment on merges to `master`. A secondary fallback job deploys static artifacts to GitHub Pages.
- **Live Production URL**: [https://mohamed-elbalooty.web.app](https://mohamed-elbalooty.web.app) (also accessible at [https://mohamed-elbalooty-portfolio.web.app](https://mohamed-elbalooty-portfolio.web.app)).
- **Firebase Project ID**: `mohamed-elbalooty-portfolio`
- **Firebase Hosting Site ID**: `mohamed-elbalooty`

## 5. Firebase Project Setup

The Firebase infrastructure is provisioned on the **Spark (No-Cost)** plan:

- **Project ID**: `mohamed-elbalooty-portfolio`
- **Hosting Site**: `mohamed-elbalooty` (Primary production URL: `https://mohamed-elbalooty.web.app`)
- **Secondary Hosting Site**: `mohamed-elbalooty-portfolio` (Fallback URL: `https://mohamed-elbalooty-portfolio.web.app`)
- **Billing**: Not enabled ($0.00/month). Complies with free tier limits (10 GB storage, 360 MB/day transfer).

### Configuration Files

#### `.firebaserc`
Binds the local project folder to the Firebase cloud project:
```json
{
  "projects": {
    "default": "mohamed-elbalooty-portfolio"
  }
}
```

#### `firebase.json`
Directs traffic, enforces clean URLs, preserves static route resolutions, and defines browser caching rules:
```json
{
  "hosting": {
    "site": "mohamed-elbalooty",
    "public": "out",
    "ignore": [
      "firebase.json",
      "**/.*",
      "**/node_modules/**"
    ],
    "cleanUrls": true,
    "trailingSlash": false,
    "headers": [
      {
        "source": "**/*.@(jpg|jpeg|gif|png|svg|webp|woff2)",
        "headers": [
          {
            "key": "Cache-Control",
            "value": "public, max-age=31536000, immutable"
          }
        ]
      },
      {
        "source": "**/*.@(js|css)",
        "headers": [
          {
            "key": "Cache-Control",
            "value": "public, max-age=31536000, immutable"
          }
        ]
      },
      {
        "source": "**/*.html",
        "headers": [
          {
            "key": "Cache-Control",
            "value": "public, max-age=0, must-revalidate"
          }
        ]
      }
    ]
  }
}
```

**Key Behaviors**:
1. `"cleanUrls": true`: Enables clean URLs without `.html` extensions (e.g. `/projects/khurdah-client` maps directly to `out/projects/khurdah-client.html`). Direct access to `/projects/khurdah-client.html` issues an automatic 301 redirect to `/projects/khurdah-client`.
2. `"trailingSlash": false`: Strips trailing slashes to prevent duplicate content indexing.
3. No Catch-All Rewrite: Omits `"rewrites": [{ "source": "**", "destination": "/index.html" }]`. Next.js static export generates discrete static files and a real `404.html`. Avoiding catch-all rewrites ensures missing pages properly return HTTP 404 to search engines.
4. Cache Headers: HTML files are served with `max-age=0, must-revalidate` so updates are instantaneous, while fingerprinted JS, CSS, and images use `max-age=31536000, immutable` for maximum speed.

## 7. GitHub Actions CI/CD Automation

Two production workflows reside in `.github/workflows/`:

### A. Pull Request Workflow ([`.github/workflows/firebase-hosting-pull-request.yml`](file:///d:/vibe%20coding/mohamed-elbalooty-portfolio-cv/.github/workflows/firebase-hosting-pull-request.yml))
- **Trigger**: Any Pull Request targeting `master`.
- **Steps**:
  1. Check out repository code.
  2. Setup Node.js 20 with npm caching.
  3. Install dependencies via `npm ci`.
  4. Run `npm run lint`.
  5. Run `npx tsc --noEmit`.
  6. Run `npm run build`.
  7. Verify output structure (`test -d out`, `test -f out/index.html`, etc.).
  8. Deploy preview channel using `FirebaseExtended/action-hosting-deploy@v0`.
  9. The action automatically posts a comment on the PR containing the preview URL.

### B. Production Deployment Workflow ([`.github/workflows/deploy.yml`](file:///d:/vibe%20coding/mohamed-elbalooty-portfolio-cv/.github/workflows/deploy.yml))
- **Trigger**: Merges or direct pushes to branch `master`.
- **Steps**:
  1. Check out repository code.
  2. Setup Node.js 20 with npm caching.
  3. Run `npm ci`.
  4. Run `npm run lint`.
  5. Run `npx tsc --noEmit`.
  6. Run `npm run build`.
  7. Verify static output (`out/index.html`, `out/404.html`, `out/sitemap.xml`, `out/robots.txt`).
  8. Deploy to Firebase live channel via `FirebaseExtended/action-hosting-deploy@v0` (`channelId: live`, `projectId: mohamed-elbalooty-portfolio`).
  9. Secondary fallback: Deploys static export to GitHub Pages via `actions/deploy-pages@v4`.

### Required Secret Setup (One-Time Manual Step)
GitHub Actions requires a Google Cloud service account key with the `Firebase Hosting Admin` role to authenticate deployments.

To configure:
1. Open the [Firebase Console Project Settings > Service accounts](https://console.firebase.google.com/project/mohamed-elbalooty-portfolio/settings/serviceaccounts/adminsdk).
2. Generate a new private key JSON, OR run the official CLI wizard:
   ```bash
   npx -y firebase-tools@latest init hosting:github
   ```
3. Copy the service account JSON contents.
4. Navigate to GitHub: [Repository Settings > Secrets and variables > Actions](https://github.com/mohamedelbalooty/mohamed-elbalooty-portfolio/settings/secrets/actions).
5. Create a new repository secret named:
   `FIREBASE_SERVICE_ACCOUNT_MOHAMED_ELBALOOTY_PORTFOLIO`
   (or `FIREBASE_SERVICE_ACCOUNT`).
6. Paste the JSON key content and save.

> [!NOTE]
> If the secret is not yet configured, the workflow safely skips the deployment step while still running and validating the lint, type-check, and build steps.

## 9. Adding a New Project Case Study

Adding a project is strictly a content operation without modifying UI components:

1. **Create Project File**:
   Create a new file in `src/data/projects/<slug>.ts` implementing the `Project` interface from [src/data/projects/types.ts](file:///d:/vibe%20coding/mohamed-elbalooty-portfolio-cv/src/data/projects/types.ts).
   ```typescript
   import { Project } from "./types";

   export const myNewProject: Project = {
     slug: "my-new-project",
     title: "Project Name",
     arabicTitle: "اسم المشروع",
     tagline: "Short summary line",
     category: "FinTech", // 'FinTech' | 'E-commerce' | 'Logistics' | 'Hospitality' | 'POS & ERP' | 'On-Demand Delivery' | 'Healthcare' | 'Enterprise SaaS'
     order: 10,
     featured: true,
     // ... problem, solution, architecture, metrics, technologies
   };
   ```
2. **Register in Index**:
   Open [src/data/projects/index.ts](file:///d:/vibe%20coding/mohamed-elbalooty-portfolio-cv/src/data/projects/index.ts), import `myNewProject`, and add it to `allProjects`:
   ```typescript
   import { myNewProject } from "./my-new-project";

   export const allProjects: Project[] = [
     // ...
     myNewProject,
   ].sort((a, b) => a.order - b.order);
   ```
3. **Verify Static Generation**:
   Run `npm run build`. Confirm that `out/projects/my-new-project.html` is generated and that the project is automatically listed in `sitemap.xml`.

## 13. Custom Domain Setup (Future Guide)

If a custom domain (e.g. `elbalooty.dev` or `mohamedelbalooty.com`) is added later:

   - Go to [Firebase Console > Hosting > Custom domains](https://console.firebase.google.com/project/mohamed-elbalooty-portfolio/hosting/sites/mohamed-elbalooty).

   - Update `siteUrl` in [src/data/site-config.ts](file:///d:/vibe%20coding/mohamed-elbalooty-portfolio-cv/src/data/site-config.ts) to the new domain.
   - Update `public/llms.txt` and `public/llms-full.txt` URLs.
   - Run `npm run build` and redeploy.

## 14. Troubleshooting

| Issue | Cause | Solution |
| :--- | :--- | :--- |
| **`npm ci` fails** | Missing or out-of-sync lockfile | Run `npm i --package-lock-only` locally and commit `package-lock.json`. |
| **Build fails on dynamic routes** | Missing `generateStaticParams` in `[slug]/page.tsx` | Ensure all dynamic route pages export `generateStaticParams()` returning array of slugs. |
| **Images not displaying** | Static export requires unoptimized images | Check [next.config.ts](file:///d:/vibe%20coding/mohamed-elbalooty-portfolio-cv/next.config.ts) has `images: { unoptimized: true }`. |
| **404 on page refresh** | Server looking for `/about` instead of `about.html` | Enforce `"cleanUrls": true` in [firebase.json](file:///d:/vibe%20coding/mohamed-elbalooty-portfolio-cv/firebase.json). |
| **GitHub Actions skips deploy** | Secret `FIREBASE_SERVICE_ACCOUNT` is empty | Add `FIREBASE_SERVICE_ACCOUNT_MOHAMED_ELBALOOTY_PORTFOLIO` to repository secrets. |
| **Turbopack memory error** | CI runner resource exhaustion | In workflow, add `NODE_OPTIONS: "--max_old_space_size=4096"`. |

## 15. Rollback and Recovery Protocols

If a broken build is deployed to production:

### Instant Firebase Console Rollback
1. Open [Firebase Console > Hosting Dashboard](https://console.firebase.google.com/project/mohamed-elbalooty-portfolio/hosting/sites/mohamed-elbalooty).
2. Locate the **Release history** table.
3. Click the three dots next to the previous healthy deployment and click **Rollback**.
4. The previous version is restored globally within seconds.

### Git Revert
```bash
git checkout master
git revert HEAD -m 1
git push origin master
```
The automated CI/CD pipeline will build and redeploy the previous clean commit.
